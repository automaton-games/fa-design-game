# ドメインドキュメント

コードベースを調査する際に、Engineering Skillがこのリポジトリのドメインドキュメントを参照するための規則です。

## 調査前に読むもの

- リポジトリルートの **`CONTEXT.md`**
- 作業対象に関連する **`docs/adr/`** 内のADR（Architecture Decision Record）

これらのファイルが存在しない場合は、警告や作成提案をせず、そのまま作業を進めてください。ドメイン用語や設計判断が実際に確定した際に、`domain-modeling` スキルが必要なファイルを作成します。

## ファイル構成

このリポジトリではsingle-context構成を使用します。

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-example-decision.md
│   └── 0002-another-decision.md
└── src/
```

## 用語集の語彙を使用する

Issueのタイトル、リファクタリング案、仮説、テスト名などでドメイン概念に名前を付ける場合は、`CONTEXT.md` で定義された用語を使用してください。用語集が避けるよう明示している同義語へ言い換えないでください。

必要な概念が用語集に存在しない場合は、プロジェクトで使われていない言葉を新しく作ろうとしていないか再検討してください。本当に不足している場合は、`domain-modeling` の対象として記録します。

## ADRとの矛盾を明示する

既存ADRと矛盾する提案を行う場合は、黙って上書きせず、どのADRと矛盾するのか、および再検討する理由を明示してください。
