# 提出DFAの入力アルファベットは問題データを唯一の情報源とする

提出DFAが扱う入力アルファベットの所有権を問題データに一元化する。
サーバーは提出を受け取った際、提出DFAへ問題の入力アルファベットを適用し、提出側が送信した `alphabet` は使用しない（無視する）。

理由: 入力アルファベットは元々問題が定義するもので、提出側に選択権がない（CONTEXT.md「入力アルファベット」）。提出と問題の両方が alphabet を持つと情報の二重管理と不整合が生じるため、問題を唯一ソースとする。

## 考慮した選択肢

- **案A: 提出にも alphabet を含め、問題の alphabet と一致するか検証する。**
  却下: 提出側に選択権のないものを検証対象にする意義が薄く、情報の二重管理と不整合のリスクを招く。
- **提出JSONの alphabet を拒否する（厳密）。**
  却下: 提出フォームが問題データから alphabet を自動補完する設計（`docs/reference/dfa-json-format.md`）と衝突し、フロントエンドが生成したJSONが拒否されてしまう。

## 帰結

- 提出DFA（未検証、alphabet は問題由来を待つ）と検証済みDFA（問題の alphabet を保持）は別の型として扱う。
- 検証済みDFAの alphabet は常に問題データに一致するため、等価性判定は alphabet 整合性を改めて検証しなくてよい。
