# 正解DFAは問題データ読み込み時に一度検証し、検証済みDFAとして保持する

正解DFAは問題データの読み込み時に一度だけ構造検証（ADR 0003）を通し、検証済みDFAとして保持する。提出ごとに再検証しない。

理由: 正解DFAは問題作成者が用意する固定データであり、提出のたびに変わらない。読み込み時に一度検証すれば、実行時には構造が保証された検証済みDFAとして等価性判定へ渡せる。

## 考慮した選択肢

- 提出ごとに正解DFAを再検証する。
  却下: 不変なデータへの冗長な再検証であり、判定レイテンシを増やすだけ。

## 帰結

- 正解DFAが読み込み時の構造検証を通らない場合、それはサーバ側の問題データ不良であり、提出者の責任ではない。提出APIは `500 Internal Server Error` として扱う（設計書のエラー分類表参照）。
- 正解DFAと提出DFAは同じドメインモデル（検証済みDFA）を用いるため、等価性判定は両者の構造を前提としてよい。
